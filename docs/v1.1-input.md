# v1.1: Interactive Input Development Notes

Status: development, preparing for push. The published v1.0.0 assets are unchanged.

## Scope

Stage 1 introduced `InputHandler`, raw Win32 keyboard input, line editing, and
persistent history (commit `a8b397f`). Stage 2 adds context-aware Tab completion.
No third-party dependency is introduced.

## Changed components

| File | Responsibility |
| :--- | :--- |
| `include/core/input.hpp` | Input API, history state, and command-name registration. |
| `src/core/input.cpp` | `ReadConsoleInputW` event loop, editing, completion, rendering, and history persistence. |
| `src/core/shell.cpp` | Supplies command names from the built-in registry after registration. |
| `src/main.cpp` | Calls the input engine and forwards submitted lines to the shell (Stage 1). |
| `Makefile` | Includes the input module in development builds (Stage 1). |

## Completion design

1. Locate the token containing the cursor. Single/double quotes keep embedded
   spaces inside the token.
2. Use only the text from the token start to the cursor as the search prefix.
3. For the first token, search the names supplied by `Shell` through
   `InputHandler::setCommandNames`. There is no duplicated hard-coded command list.
4. For arguments, separate the parent directory from the filename prefix. Resolve
   `~` using the wide-character `USERPROFILE` environment variable for directory scanning.
5. Iterate using `directory_iterator` and `increment(error_code)`. Query entry type
   using `is_directory(error_code)`. Failed or inaccessible entries are skipped;
   filesystem conversion failures are caught without terminating input.
6. Match prefixes with `CompareStringOrdinal(..., TRUE)`, sort candidates, append
   `/` to directories, and quote paths containing spaces, tabs, or apostrophes.
7. Cache candidates and the replacement span for the active Tab sequence. Each Tab
   replaces the entire active token with the next candidate, including when the
   cursor began in the middle of a token. Text outside that span stays unchanged.
8. Reset the cycle on any non-Tab key event. Redraw using `\r\033[K`, the prompt,
   and the buffer, then restore the logical cursor position.

Command-name storage is shared across InputHandler instances and assumes the
current single-shell, single-threaded architecture. The existing integration
constructs Shell before InputHandler. Future aliases or dynamically registered
commands must refresh the supplied list.

## History and console lifecycle

- History is loaded from `%USERPROFILE%/.arcnova_history` at input-handler construction.
- Non-empty interactive submissions are saved immediately; consecutive duplicates
  are omitted. The in-memory/file history is capped at 1,000 entries.
- Failed or cancelled input is not saved. Redirected input does not enter history.
- The raw console mode disables normal echo/line input and processed input while
  reading. An RAII guard restores the original mode before built-ins or external
  processes run, including on early returns.
- Ctrl+C is handled directly in the input engine and reported to the REPL.
- History is plain text. Do not enter passwords or tokens. Saves rewrite the file;
  simultaneous sessions are last-writer-wins, and writes are not atomic.

## Validation performed

- Full application compiled with C++17 and `-Wall -Wextra -Wpedantic -Wconversion
  -Wshadow -Werror` without warnings.
- Temporary assertion-based completion tests passed for command prefix matches,
  case-insensitive matching, leading whitespace, quoted path tokens, replacement
  spans with trailing text, directory suffixes, and nonexistent directories.
- Stage 1 redirected-input filesystem smoke test passed.
- A persistent regression test source is included in `tests/input_completion_tests.cpp`.
- Real interactive keyboard/rendering validation remains pending. Automated helper
  tests do not validate the terminal's cursor placement or keyboard event delivery.

## Build and automated helper test

Run from the project root in PowerShell with MinGW-w64 available in PATH:

```powershell
mingw32-make
# Helper test deliberately includes input.cpp to exercise its internal completion
# functions without exposing a new production API. Do not link input.cpp again.
g++ -std=c++17 -Wall -Wextra -Wpedantic -Wconversion -Wshadow -Werror -Iinclude tests/input_completion_tests.cpp -static -o input_completion_tests.exe
.\input_completion_tests.exe
```

The completion test reads the project include directory and creates no files.
For the icon-enabled build use `build.bat` instead of Makefile. Close installed
instances before running `install.bat` to test the latest build from Start Menu.

## Manual acceptance checklist

Use a disposable working directory with `sample.txt`, `sample-two.txt`, a
`Sample Folder` directory, and a nested directory containing files.

- [ ] Type `cl`, then Tab repeatedly: cycle `clear` / `cls` without corrupting prompt colours.
- [ ] Type `cat sam`, then Tab: cycle matching files/directories regardless of case.
- [ ] Type `cd Sam`, then Tab: produce a quoted directory path ending in `/`.
- [ ] Complete a nested path and `~/Documents/` while retaining the typed parent prefix.
- [ ] Complete inside an open double/single quote; resulting text must parse as one path.
- [ ] Move the cursor into a token followed by another argument and complete it;
      confirm the later argument is preserved.
- [ ] After a completion, edit a character or move the cursor and press Tab;
      confirm candidates are recalculated.
- [ ] Try a missing or permission-denied directory: keep the input unchanged and shell responsive.
- [ ] Test insertion, Backspace, Delete, Left/Right, Up/Down, and draft restoration.
- [ ] Press Ctrl+L with a partial command and verify prompt, text, and cursor are redrawn.
- [ ] Press Ctrl+C and confirm the line is cancelled, the next prompt is red, and input still works.
- [ ] Run an interactive external program and verify console input modes were restored.
- [ ] Restart ArcNova and verify history persistence and consecutive duplicate suppression.

## Known limitations / out of scope

- Redraw assumes one physical terminal line. Wrapping, CJK widths, combining marks,
  and grapheme-cluster editing are not fully supported; UTF-16 surrogate pairs are
  handled by basic Left/Right and deletion operations.
- Completion is for built-ins and filesystem paths only, not PATH executables,
  command-specific options, aliases, or environment-variable expansion.
- No reverse cycling with Shift+Tab, candidate menu, or common-prefix expansion.
- Filesystem iteration is synchronous and can block on slow network locations.
- History loading, concurrent writes, and atomic persistence need further hardening.
- This work does not publish a new release or modify the v1.0.0 tag/assets.
